# Cold Chain Cyber Assurance — Public PoC 5.0

[![CI / Formal Verification](https://github.com/GhostDriftTheory/verifiable-coldchain-cyber-assurance/actions/workflows/verify.yml/badge.svg?branch=main)](https://github.com/GhostDriftTheory/verifiable-coldchain-cyber-assurance/actions/workflows/verify.yml)

**Verification:** Lean 4 formal proofs (37 theorems), 768 implementation-conformance checks, and public evidence verification are validated through GitHub Actions.

**品質が正常でも、その引き渡しを実行してよいとは限らない。**

受領権限、証拠、上流の保留、実行直前の変化、実行結果を分けて確認する公開PoCです。不成立の要求を止め、正常な要求は通し、結果不一致を成功扱いしない挙動を、自分で条件を変えて確かめられます。

**操作デモ／Leanカーネル検証／実装照合／保存記録の再検証を7ファイルに集約。外部AI API実験・接続コードは含めません。**

## 1. 最初は `index.html` を開くだけ

インストール・APIキー・外部通信なしで操作できます。最初に「記録不足」を試し、不足記録を補完して再試行し、成立後に同じ要求を再送してください。「保留 → 成立 → 重複実行を拒否」を確認できます。

| 画面 | できること |
|---|---|
| 動かして比較 | 30ケースと任意の公開条件を使い、確認なし／ありの模擬操作呼出・作用・成功確定を比較。補完・再送・記録保存 |
| 実測50ケース | 既存の非公開エンジンと別プロセス模擬WMSの観測記録を閲覧。今回の公開モデルとは別枠 |
| 記録を検証 | 公開モデルの計算を再実行し、JSONの変更を検出。実測証拠は署名・観測件数・集計を照合 |
| 形式検証 | 検査済みの37命題、保証範囲、実装との対応、証明ソース、実行報告を確認 |
| 範囲と使い方 | 公開対象・非公開対象、前提条件、実WMSへの接続段階を確認 |

公開モデルでは、許可された分岐だけがローカルの模擬引き渡し関数を呼び、模擬イベントを作ります。単に判定名を切り替えるだけの画面ではありません。ただし、このタブの制御・観測は同じブラウザ内であり、独立プロセスや実WMSに接続しません。比較相手の「確認なし」も合成の対照で、現実の全AI・WMSを代表しません。

署名検証はブラウザのEd25519機能が利用できる場合のみ動きます。非対応環境では未対応と表示し、PASSにしません。その他の操作と計算記録の再検証は継続できます。静的ファイルをローカル配信する方法は `python poc.py serve` です。

## 2. 今回、実際に確認したもの

| 検査 | 結果・対象 |
|---|---|
| Lean 4.32.1 | **37命題のカーネル検査が成功**。未コンパイルのソースを成果としたものではありません |
| 実装とLeanの照合 | **768組の具体的な一致命題が成功**。公開入力192通り × 状態4通り |
| Python／画面のJavaScript | 同じ768組で、判定・理由の順序・段階・操作件数・作用件数・成功確定・次状態が一致 |
| 公開モデルの試験 | Python・JavaScriptそれぞれ**272検査が成功**。30ケース＋192入力＋形式不正・改変・補完・再送等50検査 |
| 誤った証明の拒否 | **意図的に偽とした5命題をLeanが拒否**。無権限実行、記録不足の実行、二重作用、結果不一致の成功確定、観測値改変 |
| 既存の署名付き証拠 | 50ケースの署名・結び付き・集計をPython／Nodeで検査。50件それぞれの観測変更を拒否 |

これらは対象が異なる検査です。件数を合算して「攻撃遮断数」「安全性の確率」とはしません。作成者環境での実行結果であり、第三者監査・認証ではありません。実行報告と対象のSHA-256は画面の「形式検証」に収録しています。

### 何を証明したか

`ColdChainPublic.lean` は、本PoCで公開する**7つの抽象条件と2つの状態**だけを扱います。個別製品の温度閾値、実証用の原入力、非公開エンジンの内部モデルは含めません。

中核は、不成立の条件で操作を呼ばないこと、結果不一致を隔離して成功確定しないこと、状態を保持する同じ引き渡しについて**任意長の逐次的な操作列でも模擬作用が最大1回**であることです。保留だけなら状態を消費せず、必要情報の補完後に進める正常系も確認しています。

37は定理宣言の数であり、局所的な安全性をまとめた命題とその帰結、操作列に関する帰納法などを含みます。37個の独立した新規技術を意味しません。証明穴、独自公理、`native_decide` は使用していません。依存公理の検査では、操作列の最大1回性だけがLean標準の命題外延性 `propext` を利用し、他は公理への依存なしと確認しています。

**768組の照合は、公開モデルの全型付き状態・入力に対する関数出力の一致です。Python／JavaScript全体を形式検証したという意味ではありません。** JSON解析、暗号ライブラリ、OS・ブラウザ・言語処理系、並列実行、実機の作用まで証明していません。異なる端末、プロセス再起動、状態消去、新規実行による別セッションをまたぐ最大1回性も対象外です。

## 3. 手元で再実行する

公開モデルはPython 3.10以上の標準ライブラリだけで動きます。検証に使用した環境はPython 3.13.5、Node.js 22.16.0、Lean 4.32.1、cryptography 46.0.4です。

```bash
# 操作・記録・不正入力の272検査
python poc.py test

# 30ケースを新たに実行し、記録と閲覧用HTMLを生成
python poc.py

# 保留からの回復／成立後の同じ要求の再送
python poc.py run --case missing --complete
python poc.py run --case normal --repeat

# 保存された公開モデル記録を再計算
python poc.py verify "保存先/records.json"
```

出力先の既定値はホームフォルダ内の `coldchain-assurance-results` です。公開ディレクトリへ生成物を混入させず、既存の出力先を上書きしません。画面の「新規実行」は別セッションを始め、「再送」は同じセッションの状態を保持します。

署名付き50件証拠・実装照合・形式検証には、追加で署名検証ライブラリ、Node.js、指定のLeanが必要です。

```bash
python -m pip install cryptography==46.0.4
python poc.py verify-evidence
python poc.py model-check
python poc.py formal-check
python poc.py audit
```

Leanは公式の導入手順でElan等を導入し、`lean-toolchain` の **`leanprover/lean4:v4.32.1`** を利用してください。`formal-check` は実際にLeanを起動します。証明検査、768等式、全37定理の依存公理検査、偽命題5件の拒否まで必須です。Lean未導入、版違い、証明失敗、実装不一致の際は終了コード2となり、検証成功を発行しません。

署名検証ライブラリやLeanの**初回インストール**には外部通信が必要です。PoCの操作と、導入済みツールによる検査自体は外部へデータを送りません。CIは同じ検査を行い、公開・デプロイ・成果物アップロードは行いません。

画面の「全768組の実装検査」はJavaScriptの有限検査であり、ブラウザ内でLeanを起動するものではありません。Leanを再実行するコマンドは上記です。

`evidence.json` は既存の内部実証から保存されている、最小化した署名付き証拠です。今回の公開モデルを実行した結果に差し替えたり、新しい実測として日付・内容を書き換えたりしていません。

内訳は**事前拒否37件、事後隔離7件、正常・回復5件、検出限界の負の対照1件**です。事後隔離は事前遮断ではなく、既に起きた作用の取消しでもありません。署名付きで整合した虚偽データが通過する負の対照を、防御成功に含めません。

観測は非公開エンジンとは別の模擬WMSプロセスによるものですが、同一管理者の環境です。署名は記録と鍵の結び付きを確認するもので、観測内容の真実性や組織の身元まで自動的に保証しません。必要に応じ、公開物とは別経路で確認した鍵指紋と照合してください。

```bash
python poc.py verify-evidence --expected-keyset 7f62d163c1ca4defd66919a0f539ef87ccefe13d7f7711426dcdf24e838fee27
```

同梱指紋との照合だけでは独立した身元確認にはなりません。公開検証器は署名、計画・観測・報告の対応、全50件の完備、公開した件数と集計を確認します。隠した原入力や内部の品質条件を再計算しません。証拠中の従来の330・235件等の検査値も当時の実行報告で、今回その内部テストを再実行したという意味ではありません。当時の非公開側Lean欄は `NOT_RUN` のまま保持しています。

公開モデルの計算記録は署名付きではありません。再計算とハッシュは内部整合性を確認します。入力も結果も整合するように作り直せば別の有効な記録になり得るため、発行者認証・実物流の事実証明には使いません。

## 5. 公開範囲をここで止める

| 公開するもの | 必要な理由 |
|---|---|
| 7抽象条件・2状態の一般的な公開参照モデル | 誰でも条件を変えて操作と拒否を確認できるため |
| 同じ公開モデルだけのLean定義と証明 | 形式検証を宣伝文句にせず、第三者が再検査できるため |
| 記録の再計算、署名検証、具体的出力照合 | 結果の表示と検証可能性を結び付けるため |
| ケース区分・結果・観測件数・公開鍵・署名 | 原入力を出さずに、既存実証の公開証拠を照合できるため |

**出さないもの**：非公開エンジン、製品別の詳細閾値、独自の証明生成・証拠承継・責任帰属方式、内部形式モデル、原入力、詳細トレース、実業務データ、秘密鍵、API接続実装。

これは難読化による秘匿ではありません。秘密にする処理をそもそも配布せず、公開対象を小さな参照例に限定します。公開モデルの条件・状態遷移・証明は意図的な開示です。「一切の仕組みを見せずに再現可能な形式検証」を主張しません。`audit` はファイル許可リスト、埋込データの一致、外部通信コードや秘密情報マーカーの混入等を検査する補助で、知財上の無リスクを証明する検査ではありません。

技術開示の設計はこの公開参照モデルに限定して完了しています。非公開実装と特許請求項の逐条照合、共同発表の名義承認、法的な公開許諾は別事項です。この資料は第三者企業の承認・認証や新たなライセンス許諾を表明しません。

## 6. 7ファイルの役割

| ファイル | 役割 |
|---|---|
| `index.html` | オフライン操作・比較・記録検証・形式検証の説明と実行報告 |
| `poc.py` | 公開モデル、保存記録と署名の再検証、全出力照合、Lean起動、公開物の検査 |
| `ColdChainPublic.lean` | 公開参照モデルの37命題。非公開モデルは収録しない |
| `lean-toolchain` | Lean 4.32.1固定 |
| `evidence.json` | 既存50ケースの最小化した証拠 |
| `README.md` | 使用方法・確認結果・保証範囲・開示範囲 |
| `.github/workflows/verify.yml` | 同じ公開物に対する自動検査。証明失敗を無視しない |

実出荷、実センサー、実WMSへの接続、製品品質の保証、第三者監査、規制適合はこのPoCの成果に含めません。本番導入には、観測値の来歴、永続的な一意実行、権限管理、異常時の担当者・回復手順を実環境で確認する必要があります。
